# CLAUDE.md — working on RubensAgent

Context for continuing this project from inside the repo. Read `README.md` first
for the what/how; this file captures architecture, workflow and the non-obvious
gotchas learned while building it.

## Architecture

- **Bridge daemon** (`src/`, Node ESM, deps `ws` + `node-cron`, no build step).
  Runs on the always-on Mac mini as launchd agent `nl.score.claude-bridge`,
  `0.0.0.0:8787`. `server.mjs` = HTTP + one WebSocket (`/ws`). Bearer-token auth
  (`~/.claude-bridge/token`). Reachable over Tailscale.
- **App** (`app/`, SwiftUI multiplatform iOS 17 / macOS 14). Xcode project is
  **generated by XcodeGen** from `app/project.yml` — edit the yml, not the
  `.xcodeproj`. Bundle `nl.score.claudeconsole`, Swift 5 language mode.
- **Sessions are tmux terminal-mirrors** (`src/term.mjs`): the daemon runs an
  interactive agent TUI in tmux; the app mirrors the pane via `capture-pane`
  (polled centrally by `SessionManager`) and types via `send-keys`. This
  replaced an earlier stream-json WebSocket chat model that lost live sync on
  re-entry. **The old chat code (`SessionSocket`, `SessionView`,
  `sessions.mjs` live sessions) still exists but is no longer wired into the UI.**
- **Three agents, one mechanism** (`src/agents.mjs`): Claude Code, OpenCode and
  Codex are all full-screen TUIs driven identically. The registry holds only
  what differs per agent — launch flags, the "busy" footer pattern, the login
  check. Adding a fourth agent is one entry there.

| | full-auto flag | resume | model | login check |
|---|---|---|---|---|
| `claude` | `--dangerously-skip-permissions` | `--continue` | `--model X` | keychain (not probed) |
| `opencode` | `--auto` | `--continue` | `-m provider/model` | `opencode auth list` → "N credentials" |
| `codex` | `--dangerously-bypass-approvals-and-sandbox` | `resume --last` | `-m X` | `codex login status` |

## Dev workflow

```bash
# daemon: edit src/, then deploy to the mini + restart
rsync -az --exclude node_modules --exclude .git --exclude app ./ scoremini:Projects/claude-mini-bridge/
ssh scoremini 'launchctl kickstart -k gui/$(id -u)/nl.score.claude-bridge'

# app: after ADDING a file, regenerate; then build BOTH platforms
cd app && xcodegen generate
xcodebuild -project ClaudeConsole.xcodeproj -scheme ClaudeConsole -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project ClaudeConsole.xcodeproj -scheme ClaudeConsole -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
```

- `ssh scoremini` = the Mac mini (Tailscale `100.121.84.34`). Token:
  `ssh scoremini 'cat ~/.claude-bridge/token'`.
- Verify daemon endpoints with `curl` before touching the app.
- The SourceKit "Cannot find type X" errors while editing are cross-file noise —
  `xcodebuild` is the source of truth.
- New `.swift` files aren't in the project until `xcodegen generate` runs.

## Gotchas (learned the hard way)

- **Claude auth = macOS Keychain.** The launchd daemon (a `gui/` agent) can read
  it while the mini is logged into its GUI. `claude auth status` over plain SSH
  reports `loggedIn:false` (keychain-blind) — **misleading**. For robust headless
  auth, `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN` in `~/.claude-bridge/env`.
  `run.sh` `unset`s `ANTHROPIC_API_KEY` so it's always the subscription.
- **Spawning `claude` directly from the HTTP-request handler exits immediately**
  (code 0, no output — cause unknown). The WS-handler path works fine. So
  `src/usage.mjs` runs `/usage` via a throwaway **tmux** terminal, not a direct
  spawn. Prefer the tmux path for one-shot claude runs from HTTP routes.
- **Workspace trust**: headless `claude` exits instantly in an untrusted dir.
  `src/trust.mjs` `ensureTrusted(cwd)` sets `hasTrustDialogAccepted` +
  `hasClaudeMdExternalIncludesApproved` in `~/.claude.json`. Called before
  non-bypass sessions and for memory `@import`s. `ensureAgentTrusted()`
  dispatches per agent; Codex gets a `[projects."<path>"] trust_level =
  "trusted"` block appended to `~/.codex/config.toml`, OpenCode needs nothing.
- **Busy detection**: Claude's TUI shows `esc to interrupt` in the footer only
  while working — that's how `/term/list` sets each session's `busy` flag.
  OpenCode's and Codex's footer wording has **not** been confirmed against a
  signed-in account, so those two also set `busyByChange: true` in
  `agents.mjs`: a pane that differs from the previous capture counts as
  working. Verified that an idle pane does not false-positive. Once you see the
  real footer text, add it to that agent's `busy` regex and drop the flag.
- **`opencode auth list` prints `0 credentials` when nothing is connected**, and
  `opencode models` still lists the free Zen models in that state — so model
  count is *not* an auth signal. Match on the credential count.
- **Agent availability is probed on a timer, never in a request handler**
  (same reason as the `/usage` gotcha below). `GET /agents` serves the cache;
  `?force=1` re-probes.
- **`/usage` TUI layout** is multi-line (label / bar + `N% used` / `Resets …`),
  different from the headless stream-json one — parsed in `usage.mjs`.
- **Temperature**: read via `smctemp` at the **absolute** path
  `/usr/local/bin/smctemp` (not on the launchd PATH).
- **iOS/macOS ATS**: use `NSAllowsArbitraryLoads` only. Adding
  `NSAllowsLocalNetworking` makes modern OSes ignore it, and a Tailscale (100.x)
  IP is not "local networking" → error -1022.
- **macOS sheets** need a min frame (`.frame(minWidth:minHeight:)`) or a `List`
  inside collapses. Multiple stacked `.sheet(isPresented:)` don't all present —
  use one `.sheet(item:)` enum (see `RootView`).
- **Detail column** must be wrapped in a `NavigationStack` or pushed views get no
  back button.
- **Terminal captures are polled centrally** in `SessionManager` (per-view polling
  got stuck on "Starting Claude" when switching); views read the cache.
- **File ops are confined to `~/Projects`** (`src/files.mjs` `safe()`), traversal
  rejected.
- **`gh api --paginate` for the repo list takes 10-45s**, which is why repo
  search felt broken. `src/repos.mjs` caches for 5 min (`?refresh=1` to bust)
  and the app fetches once and filters locally. Any list the app can filter
  client-side, it should — sidebar projects and branches work the same way.

## Decisions

- **Full-auto only** (`bypassPermissions`) — no in-app permission approvals.
- The daemon is intentionally dependency-light and self-contained; keep it that way.
